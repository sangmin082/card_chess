# 카드 체스 (피의 게임 파이널 3R) 앱 개발 플랜

> 5×5 보드, 말 5개, 카드 5장으로 진행하는 2인 전략 게임을 모바일/웹 앱으로 구현하기 위한 계획서.
> 원작 룰과 실제 진행 기보(1세트 23수, 2세트 22수)를 분석해 정리했다.

## 2. 룰 명세 (엔진 구현 기준)

원문 룰과 기보를 대조해 확정한 내용이다. 원문이 모호한 부분은 **[결정]** 표시와 함께 기본값을 정했고, 12절 "미결 사항"에서 다시 정리했다.

### 2.1 보드와 좌표
- 5×5 보드. 열(file) `a`~`e`, 행(rank) `1`~`5`. 기보 표기와 동일하게 `a1`, `c4`처럼 쓴다.
- 기보상 **흑은 a열, 백은 e열**에 배치되어 시작한다. 즉 각 플레이어의 "첫 줄"은 열 방향이다.
  - 흑: a1, a2, a3, a4, a5 / 백: e1, e2, e3, e4, e5
- **성(castle)**: 각 플레이어의 시작 줄 중앙 칸. 흑 성 = `a3`, 백 성 = `e3`. 성은 말이 떠나도 칸에 고정된다(기보 2세트 1수 `Aa3→b3` 이후에도 성은 a3).
- 내부 좌표는 `(file: 0..4, rank: 0..4)` 정수로 두고, 표시/기보 변환만 문자로 한다.

### 2.2 말(piece)
- 플레이어당 5개, 모두 동일한 말(폰). 이름이 없고 "어떤 카드로 움직였는지"만 기보에 남는다.
- 각 말은 **바라보는 방향(facing)** 을 가진다.
  - 백의 초기 방향: `-file` (e → a 쪽), 흑의 초기 방향: `+file` (a → e 쪽).
  - 기보 검증: `Ac2→a2x`(백, 직진 2칸 -file), `Ab3→c4x`(흑, +file 전방 대각선).
- **방향 전환**: 말이 자기 진행 방향의 마지막 줄(백은 a열, 흑은 e열)에 도착하면 방향이 반대로 바뀐다.
  - **[결정]** 반대로 돌아선 말이 다시 원래 시작 줄에 도착하면 또 한 번 뒤집힌다(왕복). 원문 "가장 마지막 줄"을 "바라보는 방향 기준 끝 줄"로 해석.
  - 방향은 어태커 카드에만 영향을 준다(다른 카드는 전방향 대칭).

### 2.3 카드와 이동 규칙
카드 5장: 룩(R), 비숍(B), 어태커(A), 나이트(N), 점퍼(J). 점퍼는 조건 충족 시 퀸(Q)으로 바뀐다.

공통 규칙:
- 목적지가 보드 밖이거나 **자기 말**이 있으면 불가.
- 목적지에 **상대 말**이 있으면 잡는다(제거).
- 별도 언급이 없으면 경로에 말이 있으면 못 지나간다(1칸 이동은 경로 문제 없음).

| 카드 | 이동 | 경로 통과 | 기보 검증 예 |
|---|---|---|---|
| 룩 R | 상하좌우 1칸 (방향 무관, 후진 가능) | - | `Rb3→a3`(후진) |
| 비숍 B | 대각선 4방향 1칸 | - | `Ba4→b3` |
| 어태커 A | (1) 바라보는 방향으로 직진 1칸 **또는** 2칸, (2) **전방** 대각선 2방향 1칸 | 직진 2칸 시 중간 칸이 비어 있어야 함 | `Aa3→b3`(1칸), `Ad3→b3x`(2칸), `Ab3→c4x`(전방 대각) |
| 나이트 N | 상하좌우 2칸 + 수직 1칸 (체스 나이트와 동일, 8방향) | 뛰어넘기 가능 | `Ne3→c4x`, `Na3→b1` |
| 점퍼 J | 인접 8칸 중 **자기 말**이 있는 방향으로, 그 말을 뛰어넘어 바로 다음 칸(거리 2)으로 이동 | 뛰어넘는 말 필수 | `Je5→e3`(e4 넘음), `Jd4→b4`(c4 넘음) |
| 퀸 Q | 상하좌우 + 대각선 8방향 1칸 | - | (기보에 등장 없음) |

- **[결정] 점퍼는 자기 말만 뛰어넘는다.** 원문은 "다른 말"이라 모호하지만, 전략 해설에 "자신만 말이 하나뿐인 상황에서는 사용 불가능"이라 명시되어 있고, 기보의 점퍼 사용 7회 모두 자기 말을 넘었다. 엔진에는 `jumperOverEnemy` 옵션을 두어 하우스룰로 전환 가능하게 한다.
- 점퍼 착지 칸에 상대 말이 있으면 잡는다(`Je2→c4x` 검증).
- **점퍼 → 퀸 전환**: 보드 위 말이 **총 2개**(1:1)가 되는 즉시, 점퍼 카드는 누가 들고 있든/대기 존에 있든 퀸으로 바뀐다. 이후 되돌아가지 않는다.
- 어태커의 "전방 대각선"은 `facing` 기준이다. 방향이 뒤집힌 말은 대각선도 반대쪽이 된다.

### 2.4 카드 배치와 순환
- 세트 시작 시 **후공**이 카드 5장 중 2장을 자기 앞에, 2장을 선공 앞에, 1장을 대기 존에 놓는다.
- 턴: 자기 카드 2장 중 1장을 골라 그 규칙으로 자기 말 1개를 옮긴다. 쓴 카드는 대기 존으로, 대기 존에 있던 카드는 내 손으로 온다.
  - 기보 검증: 1세트 시작 `백 R,J | 대기 N | 흑 B,A` → 1수 `Re3→d3` 후 `백 J,N | 대기 R`.
- 즉, 카드 흐름은 결정적이다. 항상 `내 손 2장 + 대기 1장 + 상대 손 2장 = 5장`.

### 2.5 턴 진행과 착수 의무
- 선공부터 번갈아 진행한다.
- **[결정] 두 카드 중 하나라도 합법 수가 있으면 반드시 착수해야 한다.** (해설의 "추크츠방" 언급이 근거)
- **[결정] 두 카드 모두 합법 수가 없으면** 카드 1장을 골라 대기 존과 교환만 하고 턴을 넘긴다(패스). 원문에 없으므로 옵션(`noMovePolicy: pass | lose`)으로 구현하고 기본은 `pass`.

### 2.6 승리 조건 (세트)
1. 상대 말을 모두 제거한다.
2. 상대 성 칸에 내 말을 올린 뒤 **한 턴을 버틴다**.
   - **[결정]** 내 말이 상대 성에 올라간 상태에서 상대가 한 수를 두었는데도 그 말이 성에 남아 있으면, 내 다음 턴 시작 시점에 승리. 상대가 그 말을 잡으면 무효.
   - 성에 올라간 말은 다음 턴에 그대로 두어도 되고, 다른 말을 움직여도 된다(한 턴 버티는 조건은 "성에 남아 있는지"만 본다).
- 두 조건은 중첩 가능하며 먼저 충족되는 쪽으로 즉시 종료.

### 2.7 매치 (세트 반복)
- 최대 3세트, 먼저 2세트를 이기면 최종 승리.
- **[결정] 세트마다 선/후공을 교대한다.** 기보: 1세트 강지후 선 → 2세트 윤비 선. 색(백/흑)은 유지.
- 새 세트마다 말과 카드를 초기화하고 후공이 다시 카드를 배치한다.

### 2.8 기보 표기
- 착수: `(카드)(출발)→(도착)[x]` 예: `Na1→c2x`. 앱 내부 저장은 구조화된 JSON으로 하고 표기는 파생한다.
- 세트 헤더에 색/선후공/초기 카드 배치를 기록한다.
- 원작 기보 2세트분(총 45수)을 **엔진 회귀 테스트 픽스처**로 사용한다(부록 A).

- 상태 관리는 `ChangeNotifier` 하나로 충분해 Riverpod 은 쓰지 않았다. 외부 패키지 의존성 0.

## 5. 데이터 모델

```dart
enum Color { white, black }
enum Card { rook, bishop, attacker, knight, jumper, queen }
enum Facing { minusFile, plusFile }     // 백 초기 minusFile, 흑 초기 plusFile

class Pos { final int file; final int rank; }   // 0..4

class Piece {
  final Color owner;
  final Facing facing;
}

class Move {
  final Card card;          // 사용 카드
  final Pos from, to;
  final bool capture;
}

class GameState {
  final Map<Pos, Piece> board;            // 최대 10개
  final Color toMove;
  final Map<Color, List<Card>> hands;     // 각 2장
  final Card waiting;                     // 대기 존 1장
  final Map<Color, Pos> castles;          // {white: e3, black: a3}
  final Pos? castleIntruder;              // 상대 성에 올라간 말 위치 + 누가 올렸는지
  final Color? castleIntruderOwner;
  final List<Move> history;
  final GameResult? result;               // null = 진행 중
  final RuleOptions options;              // jumperOverEnemy, noMovePolicy 등
}

class MatchState {
  final List<SetResult> sets;             // 최대 3
  final Color firstPlayerOfNextSet;
  final Map<Color, String> playerNames;
}
```

## 6. 이동 생성기 (Move Generator) 설계

`List<Move> legalMoves(GameState s, Card card)` 를 카드별로 구현한다.

```
ROOK      : 4방향 δ ∈ {(±1,0),(0,±1)}, to = from+δ, 보드 안 && !ownPiece
BISHOP    : 4대각 δ ∈ {(±1,±1)}
QUEEN     : ROOK ∪ BISHOP
KNIGHT    : 8개 δ ∈ {(±2,±1),(±1,±2)}, 경로 무시
ATTACKER  : f = facingVector(piece)          // (-1,0) 또는 (+1,0)
            직진1: from+f
            직진2: from+2f  (단 from+f 가 비어 있어야 함)
            대각 : from+f+(0,+1), from+f+(0,-1)
JUMPER    : 8방향 δ 각각에 대해
              mid = from+δ 가 자기 말이면 (옵션 시 상대 말도 허용)
              to  = from+2δ, 보드 안 && !ownPiece
```

착수 적용(`apply`) 순서:
1. 목적지 상대 말 제거 → 잡힘 기록.
2. 말 이동. 도착 칸이 자기 진행 방향 끝 줄이면 `facing` 반전.
3. 카드 순환: 손에서 카드 제거 → 대기 존 카드를 손에 추가 → 사용 카드를 대기 존에.
4. 보드 위 말이 2개면 모든 `jumper` → `queen` 치환.
5. 성 점령 판정 갱신: 도착 칸이 상대 성이면 `castleIntruder` 설정. 상대가 이전 턴에 올려둔 말이 아직 상대 성(=내 성)에 있으면 이번 내 수 이후 상대 승리 확정.
6. 전멸 판정.
7. `toMove` 교대.

## 7. 게임 흐름 상태 머신

```
MatchStart
  └─ SetStart(n)            말 초기화, 선/후공 결정
       └─ CardPlacement     후공이 [내 2장][상대 2장][대기 1장] 배치 (AI/온라인이면 자동)
            └─ Turn(color)
                 ├─ SelectCard        손의 2장 중 선택 → 합법 수 하이라이트
                 ├─ SelectPiece/Target
                 ├─ Apply             6절 순서
                 ├─ CheckSetEnd       전멸 / 성 점령 유지
                 └─ Turn(other)
       └─ SetEnd(winner)     2승이면 MatchEnd, 아니면 SetStart(n+1) (선후공 교대)
MatchEnd
```

UI 상 취소(카드 선택 취소, 말 선택 취소)를 항상 허용한다. 착수 확정 후에는 로컬 대전에서만 "무르기" 옵션 제공(설정에서 on/off).

## 8. 화면 구성 (M2 기준)

1. **홈**: 로컬 대전 / AI 대전 / 온라인(잠금) / 기보 / 규칙 설명 / 설정
2. **카드 배치**: 후공 플레이어가 5장을 드래그해 3개 슬롯(내 손 / 상대 손 / 대기)에 배치. 원작 특성상 이 단계가 전략의 핵심이라 별도 화면으로 강조한다.
3. **대전 화면**
   - 중앙 5×5 보드. 성 칸은 별도 마킹. 말은 방향(삼각형/화살표)이 보이게 그린다.
   - 상단/하단에 각 플레이어의 카드 2장, 측면에 대기 존 1장. 카드는 이동 패턴 아이콘을 함께 표시.
   - 선택한 카드 → 움직일 수 있는 말 하이라이트 → 말 선택 → 목적지 하이라이트(잡는 수는 빨강).
   - 잡힌 말 수, 세트 스코어, 턴 표시.
   - 점퍼→퀸 전환 시 카드 뒤집힘 애니메이션.
4. **세트/매치 결과**: 승리 사유(전멸 / 성 점령), 기보 저장 버튼.
5. **기보 재생**: 수 단위 전/후진, 자동 재생, 카드 흐름 표시.
6. **규칙 설명**: 카드별 이동 패턴 인터랙티브 미니보드.
7. **설정**: 하우스룰 토글(점퍼 상대 말 넘기, 무르기, 착수 불가 시 처리), 사운드, 테마.

## 9. AI 상대 (M3)

- 상태 공간이 작다(5×5, 말 ≤10, 합법 수 보통 5~20). **Negamax + alpha-beta + 반복 심화**로 깊이 6~10까지 충분히 탐색 가능.
- 평가 함수 요소:
  - 말 개수 차 (가장 큰 가중치)
  - 상대 성까지의 거리 / 성 점령 위협
  - 손에 든 카드의 기동력(합법 수 개수 합) — 특히 점퍼를 상대에게 넘기는 가치 반영
  - 말 간 인접성(점퍼 활용 가능성)
- 카드 배치(후공 시)도 탐색 대상: 5장 → (내 2, 상대 2, 대기 1) 조합 30가지를 각각 얕게 평가해 선택.
- 난이도: 쉬움(깊이 2 + 랜덤), 보통(깊이 4~6), 어려움(시간 제한 탐색 + 전치 테이블).
- 테스트: 기보의 결정적 국면(예: 1세트 c4 난전)에서 최선 수 후보에 실제 착수가 포함되는지 확인.

## 부록 A. 원작 기보 (테스트 픽스처)

형식: `턴. 카드출발→도착[x]` / 카드 표기 R B A N J Q. 홀수 턴 = 선공.

### 1세트 — 백 강지후(선) vs 흑 윤비(후)
초기 카드: 백 `R,J` / 대기 `N` / 흑 `B,A`

```
01 Re3→d3    02 Ba4→b3    03 Je5→e3    04 Ra5→b5    05 Be1→d2
06 Ja2→c4    07 Ne3→c4x   08 Bb5→c4x   09 Je2→c4x   10 Ab3→c4x
11 Bd3→c4x   12 Na3→b1    13 Re4→d4    14 Bb1→a2    15 Nd4→c2
16 Ja1→a3    17 Ac2→a2x   18 Ra3→a2x   19 Bc4→d3    20 Na2→c1
21 Jd3→d1    22 Bc1→b2    23 Nd1→b2x
결과: 백 승 (흑 전멸, 백 2개 잔존: d2, b2)
```

### 2세트 — 흑 윤비(선) vs 백 강지후(후)
초기 카드: 흑 `J,A` / 대기 `R` / 백 `B,N`

```
01 Aa3→b3    02 Be1→d2    03 Rb3→a3    04 Ne5→d3    05 Ba4→b5
06 Re4→d4    07 Nb5→d4x   08 Be3→d4x   09 Ra3→a4    10 Ne2→c3
11 Ba2→b3    12 Rc3→b3x   13 Na1→b3x   14 Ad3→b3x   15 Ja5→a3
16 Bb3→a4x   17 Ra3→a4x   18 Nd2→c4    19 Ba4→b5    20 Jd4→b4
21 Ab5→c4x   22 Rb4→c4x
결과: 백 승 (흑 전멸)
```

기보에서 확인된 사실:
- 점퍼 사용 7회 모두 자기 말을 넘었다 (`Je5→e3`, `Ja2→c4`, `Je2→c4x`, `Ja1→a3`, `Jd3→d1`, `Ja5→a3`, `Jd4→b4`).
- 어태커 직진 2칸(`Ad3→b3x`, `Ac2→a2x`), 직진 1칸(`Aa3→b3`), 전방 대각(`Ab3→c4x`, `Ab5→c4x`) 모두 등장.
- 말이 끝 줄에 도달한 사례: `Ac2→a2x`(백, a열), `Bb3→a4x`(백, a열). 둘 다 다음 수에 잡혀 방향 전환 후 어태커 이동은 기보로 검증 불가.
- 2세트 21수(`Ab5→c4x`) 뒤 백 1 : 흑 1 로 보드에 말이 2개만 남는다. 룰대로면 이 시점에 점퍼가 퀸이 되어야 하지만 원작 진행표는 계속 `J`로 적고 있다. 엔진은 룰 원문을 따라 퀸으로 바꾸고, 재생 테스트는 이 차이를 정규화해 비교한다.
